## 8. Masalah diketahui / utang teknis
- **T5c1b selesai tetapi BELUM dirakit dan BELUM ada rute:** `RoleHandlers` harus dibuat di T5d: `authzhttp.NewRoleHandlers(rs, repository.NewRoleReader(pool), roleWriter, repository.NewPermissionReader(pool))` lalu `h.Mount(r, mw.Authorize)` di dalam grup yang SUDAH melewati Authenticate → CSRF → RequireAuth → `mw.Scope` (ADR-0022 butir 25). `Mount` hanya memasang `Authorize` per rute; urutan middleware di atasnya adalah tanggung jawab perakit. Tes ujung-ke-ujung lewat server nyata (dan CSRF untuk rute mutasi) baru ada di T5e.
- **`PATCH /roles/{id}` dapat saling menimpa:** handler membaca nama+deskripsi berlaku di luar transaksi `RoleWriter.UpdateRole` lalu menulis keduanya; dua PATCH serentak pada field berbeda dapat menghilangkan salah satu perubahan (ADR-0022 butir 64f). Penutupnya (masukan opsional di penulis) belum dikerjakan.
- **Keterbatasan jalur baca (tidak ada jaminan absolut; butir 63):** pemanggil dengan grup aktif yang memegang `role.read` melihat SEMUA role organisasinya (bukan hanya role grupnya); total dan halaman dibaca dengan dua kueri sehingga dapat berselisih sesaat; urutan `(created_at, id)` bergantung pada id UUIDv7 untuk stabilitas; katalog permission belum menyaring permission modul nonaktif (docs/06 §14, M07); jalur baca tidak mengaudit pembacaan.
- **Helper paginasi offset ada di `authzhttp` (`parsePaging`, `windowFor`, `paginationMeta`):** T5c2b (`GET /policies`) memakainya ulang; `GET /role-assignments` memakai cursor (`httpx.ParsePage`/`Paginate`), bukan ini.
- **Anotasi swagger T5c1b menunggu commit `chore(generate)`:** jangan lanjut ke patch berikutnya sebelum `git status --short` bersih dan `docs/api/swagger.json` ter-commit (hasil commit/push tidak ditempel saat dokumen ini ditulis).

- **[Diperbarui partial-12: `RoleHandlers` kini memakai `DomainError` dan DTO role; tetap belum dirakit dan belum ada rute] T5c1a selesai tetapi belum dipakai handler:** `DomainError` dan DTO role belum punya pemanggil; tidak ada rute. Kewajiban mengikat (ADR-0022 konsekuensi bagian 13): sentinel baru di domain atau penulis WAJIB ditambahkan ke `programmingErrors`, `codeRules`, atau `fieldRules`; yang terlewat jatuh ke 503 (terlihat di log), bukan izin.
- **[Diperbarui partial-12: jalur BACA role dan permission SUDAH ada (T5c1b-1, butir 63); assignment dan policy belum] Jalur BACA belum ada** (GET roles, role permissions, permissions, role-assignments, policies): dibutuhkan T5c1b–T5c2b; setiap kueri wajib memfilter organisasi (tenant melihat role organisasinya + template sistem; assignment organisasinya; policy organisasinya + global) dengan tes negatif lintas organisasi (docs/12 §6 butir 3).
- **Risiko replay Idempotency-Key lintas scope (belum dibuktikan, perlu tes di T5c2a):** `Subject` idempotensi = user id, rute = pola chi, hash = method + rute + query + body; organisasi tidak ikut hash karena diturunkan dari scope. Super Admin yang pindah organisasi lalu mengirim kunci dan body sama dapat menerima respons asli organisasi sebelumnya tanpa eksekusi. Mitigasi yang mungkin: memasukkan scope (organisasi/grup aktif) ke hash atau ke subjek untuk rute ini. `Idempotency.Require()` dipasang SETELAH `Authorize(role.assign)` supaya admin yang haknya dicabut tidak dapat memutar ulang respons lama. Redis mati = POST `/role-assignments` gagal-tertutup 503 (dikehendaki docs/08 §6).
- **Keterbatasan pemetaan galat yang dicatat (ADR-0022 konsekuensi bagian 13; tidak ada jaminan absolut):** (a) `ErrInvalidGrant` di jalur tulis tampil sebagai 400 walau berasal dari data rusak (penyebab di log); (b) `repository.ErrNoTransaction` tampil 503 bukan 500; (c) posisi galat ekspresi policy tidak dikembalikan ke admin (usulan: field `position` terstruktur dari parser); (d) `ErrGroupNotFound` selalu field `group_id`.
- **Insiden lingkungan sesi partial-11:** tiga kegagalan kelas Docker pada run utuh (`container is marked for removal`; `Reaper handshake failed … connection reset by peer` + `RWLayer … is unexpectedly nil`; `wait for reaper … context deadline exceeded`), semuanya hijau sendirian; dan daemon Docker tampak restart di tengah `verify-smoke.sh`, memutus sesi WSL (penyebab tidak terbukti). Detail dan urutan penanganan: §3 dan §7.
- **Run `make verify` utuh hijau terakhir tetap pada `2b7d781`;** HEAD ◆CP7 `exit=2` (kelas Docker, §3); tidak ada run utuh pada kode T5b3/T5b4/T5c1a. Satu run utuh disarankan setelah T5d.
- **T5b4 selesai tetapi BELUM dirakit:** `PolicyWriter` belum dibuat di `newAuthzStack`/`internal/app` dan tidak ada endpoint; belum ada perilaku HTTP baru. Tes memakai PostgreSQL sungguhan; tidak ada invalidator (policy tidak di-cache), jadi tidak ada gabungan Redis yang belum dites untuk policy. Perakitan di T5d (§5).
- **`PolicyWriter` tidak memeriksa permission pemanggil dan tidak menerapkan authority ceiling** (policy hanya membatasi): endpoint WAJIB memasang `Authorize("policy.manage")`/`Authorize("policy.read")`; `Grantor.Scope` dari `ScopeContext`. Bila endpoint salah memberi `Scope` (mis. platform untuk request tenant), penulis akan menulis policy GLOBAL; T5c harus menurunkan `Grantor` hanya dari `ScopeContext` yang dihasilkan middleware `Scope`, tanpa menerima organisasi dari body/path.
- **Keterbatasan `PolicyWriter` yang dicatat (tidak ada jaminan absolut; ADR-0022 konsekuensi bagian 12):** (a) tulis policy global (kunci platform) dan organisasi (kunci organisasi) tidak diserialkan satu sama lain; batas dihitung per cakupan; (b) perlindungan butir 59 hanya untuk pengelolaan policy: policy `deny` pada aksi lain (mis. `role.manage`) tetap dapat menutup kemampuan itu sampai `policy.manage` menonaktifkannya, dan policy global hanya dapat dinonaktifkan pemanggil platform; (c) katalog dimuat sekali per tulis, modul yang mendaftar bersamaan dapat terlewat dalam jendela milidetik; (d) policy yang actions-nya hilang dari katalog hanya dapat dinonaktifkan atau diperbaiki; pembersihan di M07; (e) tidak ada riwayat versi policy: nama/deskripsi/ekspresi lama tidak tersimpan di audit; (f) tidak ada endpoint baca daftar policy di repositori (hanya `ForAction`); `GET /policies` (T5c) butuh kueri baca baru (§9).
- **Insiden image Docker (sesi partial-10):** `postgres:18` hilang dari cache lokal di tengah sesi; tes ber-DB menggantung sampai batas waktu (bukan gagal cepat) dan menyerupai flake reaper. Pemeriksaan pertama untuk kelas ini: `docker image ls postgres` (§7). Sebab hilangnya image tidak diketahui (kemungkinan: pembersihan Docker Desktop atau reset penyimpanan). Waktu run setelah pulih (`application` 284 dtk) jauh di atas baseline ±80 dtk dan sebabnya tidak dibuktikan; bila terulang, ukur dengan `-v` dan bandingkan.
- **T5b2 selesai tetapi BELUM dirakit:** `RoleWriter` belum dibuat di `newAuthzStack`/`internal/app` dan tidak ada endpoint; belum ada perilaku HTTP baru. Tes memakai invalidator tiruan; `cache.Cache.InvalidateInTx` teruji sendiri (T3c) tetapi gabungan `RoleWriter` + `Cache` + Redis nyata belum dites ujung-ke-ujung. SYARAT untuk setiap penulis BARU (modul M05+ yang mengubah role, assignment, atau policy): ambil kunci yang sama sebagai langkah pertama; tanpa itu celah ceiling-lalu-tulis dan lewat-batas-50 terbuka kembali.
