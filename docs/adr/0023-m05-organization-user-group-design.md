# ADR-0023 — M05: keputusan desain Organization, User, Group, Invitation, Email (bagian 1-3: T1a-1, T1a-2, T1a-3a dan T1a-3b)

**Status:** Diterima untuk kode yang sudah ditulis; butir bertanda **BELUM dikonfirmasi** dipakai sebagai default sampai pemilik membantah · **Tanggal:** 2026-11-20 · **Konteks:** M05 partial-2 (paket `internal/organization`: domain, repository, application); partial-3 (T1a-3a: domain dan repository anggota organisasi, butir 11-14). Bagian berikutnya ditambahkan per task; butir diberi nomor lanjut.

## Konteks
docs/02 §6 mendefinisikan organisasi dan statusnya, docs/08 §10.6 rutenya, tetapi tidak menetapkan batas tenant pada tabel `organizations` (akar tenant, tanpa kolom `organization_id`), siklus status, bentuk masukan, atau nama audit dan event. Keputusan di bawah menutup celah itu untuk T1a-1 dan T1a-2. Semuanya dibuktikan di laptop pemilik (tes tiga paket hijau; lihat HANDOVER-M05-partial-2 §3), tidak ada migrasi baru (migrasi terakhir tetap 035).

## Keputusan
1. **Batas tenant pada `organizations` = `domain.Access`.** Setiap metode repository menerima `Access`: `PlatformAccess()` (hanya dibentuk bila ScopeContext request bersifat platform) atau `TenantAccess(organizationID)` (organisasi dari ScopeContext, bukan dari body, path, atau query). Nilai nol `Access` DITOLAK (`ErrInvalidAccess`), sehingga lupa mengisi scope tidak pernah menjadi akses platform. Pembatasnya adalah `o.id = $1 AND ($2::uuid IS NULL OR o.id = $2::uuid)` di setiap kueri baca dan tulis. Pemanggil tenant yang menunjuk organisasi lain mendapat `ErrOrganizationNotFound` dengan pesan identik dengan id yang tidak ada (tidak ada oracle lintas tenant). `Insert` hanya untuk platform (`ErrPlatformRequired` untuk tenant). Ini mengimplementasikan usulan desain 1 (HANDOVER-M05-partial-1 §4).
2. **Siklus status:** `active` dan `suspended` saling berpindah, keduanya dapat diarsipkan, `archived` TERMINAL (tidak ada jalan keluar; docs/02 tidak menyebut jalur kembali, jadi pilihan teraman). Perpindahan ke status yang sama ditolak (`ErrInvalidTransition`). Satu `UPDATE` bersyarat status asal (`domain.PredecessorStatuses`) lalu kueri diagnosis membedakan "tidak ada atau bukan milikmu" (`ErrOrganizationNotFound`) dari "ada tetapi transisi tidak sah". Mengarsipkan mengisi `status = 'archived'` DAN `deleted_at` (kode otorisasi `Effective` mensyaratkan `status = 'active' AND deleted_at IS NULL`). **BELUM dikonfirmasi** (terminal).
3. **Bentuk masukan.** `slug`: 2–100 karakter, pola ASCII `huruf/angka` dipisah satu tanda hubung, pola diperiksa SEBELUM pelipatan huruf kecil (tanda Kelvin dan sejenisnya tidak lolos), TIDAK dapat diubah lewat PATCH. `name`: 1–200 rune, tanpa karakter kontrol, UTF-8 sah. `legal_name`: paling banyak 255 rune; string kosong = NULL. `default_locale`: pola sederhana BCP 47 (`en`, `id-ID`, `zh-Hant-TW`), paling banyak 20. `default_timezone`: nama IANA divalidasi dengan `time.LoadLocation`; `time/tzdata` ditanam di paket domain supaya hasilnya tidak bergantung pada image runtime (±450 KB pada biner). Tidak ada daftar slug yang dicadangkan (pertanyaan terbuka bila slug dipakai di URL atau subdomain). **BELUM dikonfirmasi.**
4. **Daftar organisasi:** filter `open` (bawaan: active dan suspended), `all`, atau satu status; urut `(created_at, id)`; `Window` bawaan 50, maksimum 100 (usulan desain 4; paket authorization tetap memakai 25); total dan halaman dibaca dengan dua kueri sehingga dapat berselisih bila data berubah di antaranya. Pemanggil tenant paling banyak melihat satu organisasi (daftar satu item); docs/08 menyebut "their memberships", tetapi di model ScopeContext satu request berarti satu organisasi, dan daftar keanggotaan lintas organisasi lebih cocok di endpoint `/me`. **BELUM dikonfirmasi.**
5. **`Service.Archive`** (`DELETE /organizations/{id}`): kunci advisory organisasi (`LockOrganization`, kunci yang sama dengan penulis role/assignment/policy; butir 54 ADR-0022) diambil sebagai langkah PERTAMA transaksi, lalu `ForUpdate`, `SetStatus`, `InvalidateInTx` (cache otorisasi dinaikkan di dalam transaksi SEBELUM audit dan event), audit, event. Kegagalan di langkah mana pun membatalkan semuanya (dibuktikan ber-DB: invalidasi gagal = status dan `deleted_at` kembali). Pemanggil tenant yang menunjuk organisasi lain ditolak SEBELUM transaksi dibuka, sehingga tenant tidak dapat "meraba" kunci milik organisasi lain. Pencabutan sesi sesudah commit adalah urusan T5 (cakupan diputuskan setelah skema sesi dibaca).
6. **`Service.Update`** (name, legal_name, default_locale, default_timezone): baca dengan kunci baris (`ForUpdate`), organisasi terarsip = `ErrOrganizationArchived`. Pembaruan yang tidak mengubah nilai apa pun mengembalikan keadaan sekarang TANPA menulis, mencatat audit, atau menerbitkan event. Audit dan event memuat NAMA bidang yang berubah (terurut), tidak pernah nilainya. `Create` hanya untuk platform; organisasi baru belum punya anggota atau cache sehingga tidak ada invalidasi dan tidak ada kunci.
7. **Penamaan** (docs tidak mendefinisikan nama untuk organisasi; mengikuti pola `<entitas>.<bentuk lampau>` seperti `user.profile_updated` di docs/02 §7): audit `organization.create`, `organization.update`, `organization.archive`; event `organization.created`, `organization.updated`, `organization.archived` (`AggregateType` `organization`, `AggregateID` = id organisasi). `Actor.OrganizationID` pada audit diisi ORGANISASI SASARAN (termasuk saat operator platform bertindak) supaya administrator organisasi melihatnya di log auditnya sendiri. **BELUM dikonfirmasi.**
8. **`application.Caller`** = user yang bertindak + `ScopeContext`. `UserID` kosong ditolak (`ErrInvalidAccess`). `ScopeContext` nol berarti scope platform (semantik M04), jadi hanya middleware `Scope` yang boleh membentuknya. Pemeriksaan permission aksi tetap tugas middleware `Authorize`; layanan menegakkan batas tenant (pertahanan lapis kedua).
9. **Enam usulan desain di HANDOVER-M05-partial-1 §4 tetap dipakai sebagai default dan tetap BELUM dikonfirmasi** (accept-invitation akun yang sudah ada tanpa mengatur password; TTL undangan 72 jam dan reset 30 menit; paginasi offset untuk organisasi/user/grup dan cursor untuk anggota/undangan; `DELETE` organisasi = archived; 409 email yang sudah ada = oracle bagi admin, dicatat). Butir 1 dan 5 di atas adalah penerapan butir 1 dan 5 usulan itu.
10. **Sentinel baru WAJIB didaftarkan** di pemetaan galat HTTP (T1a-4; yang terlewat jatuh ke 503): `ErrOrganizationNotFound`, `ErrSlugTaken`, `ErrPlatformRequired`, `ErrInvalidAccess`, `ErrNoTransaction` (galat pemrograman), `ErrInvalidTransition`, `ErrOrganizationArchived`, `ErrNothingToUpdate`, `ErrInvalidID`, `ErrInvalidName`, `ErrInvalidLegalName`, `ErrInvalidSlug`, `ErrInvalidLocale`, `ErrInvalidTimezone`, `ErrInvalidStatus`, `ErrInvalidFilter` (semua di `internal/organization/domain`).
11. **Anggota organisasi (`organization_memberships`) — aturan inti (BELUM dikonfirmasi).** (a) `Add` HANYA untuk `Access` platform dan hanya untuk user aktif yang belum dihapus; status awal `active` (`joined_at` = sekarang, `invited_by` = pemberi bila ada). `Access` tenant mendapat `ErrPlatformRequired` dan tidak ada yang ditulis: admin tenant tidak boleh menarik user sembarang ke organisasinya; tenant memakai undangan (T4). (b) `Remove` = penghapusan logis (`status = 'removed'`; baris dan user tetap ada; docs/02 §9 aturan 2). Anggota yang tidak ada, sudah dihapus, atau milik organisasi lain = `ErrMemberNotFound` yang sama. (c) Menambah ulang anggota `removed` memakai ulang baris yang sama (`uq_org_memberships`; `joined_at` dan `invited_by` diperbarui). Anggota `active`, `invited`, atau `suspended` = `ErrMemberExists`. User yang tidak ada, tidak aktif, atau dihapus-lunak = `ErrUserNotEligible` (satu galat untuk ketiganya); reaktivasi baris `removed` milik user yang tidak layak ditolak. (d) Pemanggil tenant tidak boleh menghapus keanggotaannya sendiri lewat endpoint ini (diterapkan di service T1a-3b; sentinel `ErrCannotRemoveSelf` dialokasikan di sana). Pelindung "admin terakhir organisasi" BELUM ada (utang). (e) Penulisan ke organisasi `archived` ditolak `ErrOrganizationArchived` (service T1a-3b).
12. **Daftar anggota (BELUM dikonfirmasi).** Cursor buram atas `(created_at, id)`: base64url tanpa padding dari `<mikrodetik>.<uuid>`, ketelitian mikrodetik (sama dengan `timestamptz`), bentuk non-kanonik ditolak, maksimum 200 karakter. Ukuran halaman bawaan 50 dan maksimum 100 (`ClampMemberLimit`; usulan desain 4). Filter `open` (bawaan: invited, active, suspended), `all`, atau satu status; filter dan cursor tak dikenal = `ErrInvalidFilter` dan `ErrInvalidCursor` sebelum kueri. Hasil memuat `user_id`, `display_name`, status keanggotaan, dan `users.status`, TANPA email (email lewat jalur user dengan field permission di T1b). `Access` tenant yang menunjuk organisasi lain mendapat `ErrOrganizationNotFound` (sama dengan organisasi yang tidak ada). `Get` mengembalikan baris berstatus apa pun, termasuk `removed`.
13. **Akibat penghapusan anggota (BELUM dikonfirmasi; diselesaikan di service T1a-3b).** Dalam satu transaksi dengan kunci advisory organisasi sebagai langkah PERTAMA: keanggotaan menjadi `removed`; keanggotaan GRUP user di organisasi itu menjadi `removed` (`RemoveFromGroups`, sudah ada di repository); role assignment ber-scope organisasi dan grup milik user itu dicabut (`revoked_at`) supaya tidak hidup lagi saat user ditambahkan kembali (BELUM ada: butuh metode baru di `authorization/repository`); `InvalidateInTx`; audit; event. Akses sudah tertutup seketika karena `Effective` mensyaratkan keanggotaan `active` untuk scope organisasi dan grup (`authorization/repository/effective.go`); assignment ber-scope platform tidak butuh keanggotaan. Sesi TIDAK dicabut oleh `Remove`: keanggotaan hanya diperiksa saat login dan pindah organisasi (`auth/service/auth.go`), sehingga sesi ber-scope organisasi itu tetap ada sampai T5 memutuskan pencabutan per (user, organisasi) (usulan desain 5).
14. **Penamaan dan sentinel anggota (BELUM dikonfirmasi).** Audit `organization.member.add|remove` dan event `organization.member.added|removed`. Audit berbentuk imperatif mengikuti perilaku nyata M04 (`role.create`, `role_assignment.revoke`) dan butir 7, bukan bentuk lampau contoh docs/13; ADR terbaru menang. Sentinel baru yang WAJIB didaftarkan di pemetaan galat HTTP (T1a-4; yang terlewat jatuh ke 503): `ErrMemberNotFound`, `ErrMemberExists`, `ErrUserNotEligible`, `ErrInvalidCursor` (dan `ErrCannotRemoveSelf` bila ditambahkan di T1a-3b). Kode HTTP ditetapkan di T1a-4 mengikuti pola `DomainError`; usulan awal: 404, 409, 422, 400.
15. **Pencabutan assignment saat anggota dihapus (BELUM dikonfirmasi; dibangun di commit `d2ad0c4`).** `Assignments.RevokeUserInOrganization(ctx, organizationID, userID) (int, error)` di `authorization/repository` mencabut (`revoked_at = now()`) setiap assignment aktif yang subjeknya user itu dan yang kolom `organization_id`-nya organisasi itu: scope organisasi (kedua bentuk kanonik), grup, serta resource dan own yang terikat organisasi (resource dan own hari ini tidak dievaluasi mesin, tetap dicabut supaya tidak hidup lagi saat keanggotaan diaktifkan kembali). Tidak menyentuh assignment platform (`organization_id` NULL), organisasi lain, subjek grup atau organisasi, dan baris yang sudah dicabut (`revoked_at` aslinya tetap). Mencabut hanya mengurangi hak, jadi tidak butuh pemeriksaan ceiling. Wajib di dalam transaksi (`ErrNoTransaction` di luar) dan pemanggil memegang `LockOrganization` sebagai langkah pertama (butir 54 ADR-0022). Tabel hanya punya `revoked_at` (tanpa kolom pencabut). Menambah ulang anggota TIDAK menghidupkan assignment lama: yang baru dibuat lewat jalur assignment biasa (dengan ceiling).
16. **`MemberService` (T1a-3b; BELUM dikonfirmasi).** (a) Layanan terpisah dari `Service` organisasi: `NewMemberService(tx, members, orgs, revoker, locker, audit, events, inv)` dengan antarmuka `MemberStore`, `OrganizationReader`, `AssignmentRevoker`; `inv` boleh nil (tanpa Redis). (b) `Add`: Access tenant mendapat `ErrPlatformRequired` SEBELUM transaksi (tidak ada kunci yang diambil); id nil = `ErrInvalidID`; transaksi: `LockOrganization` PERTAMA, baca organisasi, `ErrOrganizationArchived` bila status `archived` atau `ArchivedAt` terisi, `Members.Add` (`invited_by` = pemanggil), `InvalidateInTx` (`Targets{Organizations}`), audit, event. Organisasi `suspended` BOLEH menerima anggota baru dari platform (hak efektif tetap kosong karena `Effective` mensyaratkan organisasi aktif). `invited_by` berkunci asing ke `users`: pemanggil `Add` harus user yang ada. (c) `Remove`: Access valid; id nil = `ErrInvalidID`; tenant yang menunjuk organisasi lain = `ErrOrganizationNotFound` SEBELUM transaksi (kunci organisasi lain tidak diraba); tenant yang menghapus dirinya sendiri = `ErrCannotRemoveSelf` (butir 17); transaksi: kunci PERTAMA, organisasi (archived ditolak), `Members.Remove` (`ErrMemberNotFound`), `RemoveFromGroups`, `RevokeUserInOrganization`, `InvalidateInTx`, audit, event; kegagalan di langkah mana pun membatalkan semuanya dan tidak meninggalkan audit atau event. Sesi TIDAK dicabut (T5). (d) Audit `organization.member.add|remove` dengan `ResourceType` `organization_membership`, `ResourceID` = id baris keanggotaan, metadata hanya id dan hitungan (`user_id`, `status`; `groups_removed`, `assignments_revoked`) dan `Actor.OrganizationID` = organisasi sasaran; event `organization.member.added|removed` dengan `AggregateType` `organization_membership`, `AggregateID` = id baris keanggotaan, payload `organization_id`, `actor_user_id`, `user_id` ditambah metadata yang sama; tidak pernah email atau nama. (e) `Get` dan `List` hanya meneruskan Access ke repository: `Get` lintas organisasi = `ErrMemberNotFound` (repository `Get`), `List` lintas organisasi = `ErrOrganizationNotFound`. (f) Dua `Remove` serentak untuk user yang sama: tepat satu lolos, yang lain `ErrMemberNotFound`; dua `Add` serentak: tepat satu lolos, yang lain `ErrMemberExists`.
17. **`ErrCannotRemoveSelf` dan daftar sentinel anggota untuk pemetaan HTTP (BELUM dikonfirmasi).** `domain.ErrCannotRemoveSelf` hanya berlaku untuk Access tenant; operator platform tidak dibatasi. Sentinel anggota yang WAJIB didaftarkan di pemetaan galat HTTP pada T1a-4 (yang terlewat jatuh ke 503): `ErrMemberNotFound`, `ErrMemberExists`, `ErrUserNotEligible`, `ErrInvalidCursor`, `ErrCannotRemoveSelf`, selain `ErrOrganizationArchived` dan `ErrPlatformRequired` dari butir 10. Usulan kode HTTP awal: 404, 409, 422, 400, 409; ditetapkan di T1a-4 mengikuti pola `DomainError`. Pelindung "admin terakhir organisasi" tetap BELUM ada (utang).
18. **Pemetaan galat HTTP organisasi dan `RequireTenant` (BELUM dikonfirmasi).** (a) Lapisan HTTP organisasi ada di paket `internal/organization/transport/http` (nama paket `orghttp`, meniru `authzhttp`): kode error, `DomainError`, DTO, dan handler. (b) Delapan kode API baru: `organization_not_found` 404, `member_not_found` 404, `organization_slug_taken` 409, `organization_archived` 409, `invalid_status_transition` 409, `member_exists` 409, `cannot_remove_self` 409, `user_not_eligible` 422. (c) Sentinel lain: `ErrPlatformRequired` menjadi `permission_denied` 403 yang seragam (tenant tidak mendapat petunjuk tentang operasi platform-saja); `ErrInvalidAccess`, `ErrNoTransaction`, `ErrInvalidID`, `ErrInvalidStatus` menjadi `internal_error` 500 (tidak dapat berasal dari klien yang lolos DTO dan middleware; `ErrInvalidStatus` hanya muncul dari `Record.Validate` dan `PredecessorStatuses`); `ErrInvalidName`, `ErrInvalidLegalName`, `ErrInvalidSlug`, `ErrInvalidLocale`, `ErrInvalidTimezone` menjadi `validation_failed` dengan `details.fields` pada field DTO-nya (`name`, `legal_name`, `slug`, `default_locale`, `default_timezone`); `ErrInvalidFilter` menunjuk field `status` (nama parameter query); `ErrInvalidCursor` menunjuk field `cursor` dengan kode `invalid_cursor`; `ErrNothingToUpdate` memakai kode `empty_patch`; galat tak dikenal menjadi 503 (gagal-tertutup). Pesan tetap dan tidak memuat nilai klien. (d) `TestEveryExportedSentinelHasAMapping` membaca KODE SUMBER paket domain, application, dan repository organisasi (`go/parser`) dan mensyaratkan setiap variabel terekspor berawalan `Err` punya baris di tabel tes dan aturan di `DomainError`: sentinel baru tanpa pemetaan menggagalkan tes alih-alih jatuh ke 503. (e) `authzhttp.Middleware.RequireTenant` (urutan: Authenticate, CSRF, RequireAuth, Scope, RequireTenant, Authorize): scope tenant (dengan atau tanpa grup aktif) diteruskan; scope platform ditolak `400 invalid_scope` (operator platform harus memilih organisasi lebih dulu; kesalahan klien, bukan 403); tanpa ScopeContext 500 gagal-tertutup. Pemakai nyata pertamanya rute grup (T1c); handler `/organizations` melayani platform dan tenant sehingga tidak memakainya.
19. **Aksi per rute dan bentuk endpoint organisasi dan anggota (BELUM dikonfirmasi).** (a) Aksi: `GET /organizations` dan `GET /organizations/{id}` = `organization.read`; `POST /organizations` = `organization.create`; `PATCH /organizations/{id}` = `organization.update`; `DELETE /organizations/{id}` = `organization.archive`; semua rute anggota, termasuk baca, = `organization.member.manage` (katalog tidak punya kode baca-anggota dan daftar anggota membuka identitas pengguna, jadi dipilih yang paling ketat; kode baru dapat ditambah kemudian; katalog tetap 41 kode). (b) Pemanggil (`Caller`) diturunkan dari Identity dan ScopeContext; organisasi sasaran dari path `{id}` dan diteruskan apa adanya ke layanan, yang memagarinya lewat `domain.Access` (tenant yang menunjuk organisasi lain mendapat 404 seragam). `{id}` atau `{user_id}` yang cacat atau UUID nol = 404 (`organization_not_found` atau `member_not_found`) tanpa menyentuh layanan. (c) Body didekode `DecodeJSON` (field tak dikenal ditolak): DTO tidak punya `id`, `status`, atau `organization_id`; DTO ubah tidak punya `slug` (slug tak dapat diubah; mengirimnya = `unknown_field`); PATCH kosong (semua field hilang atau null) = 400 `empty_patch`; `legal_name` berisi string kosong menghapus nilainya. (d) `POST /organizations` tidak mewajibkan `Idempotency-Key` (slug unik membuat retry menjadi 409, bukan duplikat); rute undangan (T4) yang mewajibkannya lewat `TenantIdempotency`. (e) Daftar organisasi: offset (`page` 1..10000, `per_page` bawaan 50 dan dipangkas ke 100), `meta.pagination {page, per_page, total}`, parameter `status` (`open` bawaan, `all`, atau satu status). Daftar anggota: cursor buram milik domain (bukan `httpx.Cursors`; tidak terikat hash filter), `limit` (50/100), `cursor`, `status`; `meta.pagination {next_cursor, has_more}` (`next_cursor` null pada halaman terakhir). (f) `DELETE` organisasi dan anggota = 204 tanpa body; `POST` = 201; `GET .../members/{user_id}` ditambahkan di luar daftar docs/08 §10.6 karena layanan punya `Get`. (g) Respons anggota tanpa email dan tanpa `organization_id` (butir 12). (h) Perakitan (T1a-4c): `orghttp.Handlers.Mount(r, authorize)` panik bila `authorize` nil; jalur relatif dan prefiks `/api/v1` dipasang perakit; anotasi swag sudah ada, tetapi swagger baru terhasilkan sesudah `orghttp` masuk graf impor `main`.

20. **Perakitan rute organisasi dan anggota di RunAPI (bagian 4: T1a-4c; BELUM dikonfirmasi).** (a) `authzStack.organizationRoutes(pool, audit, responder, log)` (`internal/app/organization.go`) merakit repository organisasi dan anggota, `Service`, `MemberService` dan `orghttp.Handlers` di atas satu `TxManager`, satu `Bus`, kunci advisory `authzrepo.LockOrganization` (sama dengan penulis role, assignment dan policy; ADR-0022 butir 54) dan `txInvalidator` milik stack (interface nil tanpa Redis, diteruskan sebagai interface nil, bukan pointer nil terbungkus). Fungsi ini hanya merakit objek (tanpa I/O) dan menolak perekam audit atau Responder nil. (b) Mounter ini TIDAK dimasukkan ke `httpAPI`: `RunAPI` menambahkannya ke `authzAPI.Routes` sesudah `httpAPI` (hanya bila pool PostgreSQL ada, sama dengan rute otorisasi), sehingga tabel 15 rute M04 (`TestAuthzHTTPAPIMountsExactlyTheConfirmedRoutesWithTheirActions`) tetap utuh dan rute organisasi memakai Middleware yang sama (`RequireAuth`, `Scope`, lalu `Authorize(action)` per rute). (c) Tabel sembilan rute beserta aksinya dijaga `TestOrganizationRoutesMountExactlyTheConfirmedRoutesWithTheirActions`; perakitan tanpa audit atau Responder ditolak (`TestOrganizationRoutesRefuseToAssembleWithoutAuditOrResponder`). (d) USULAN tes ber-DB perakitan (c2, belum ditulis): paket `app_test` dengan jembatan di `export_test.go` (siklus impor `app` -> `testkit` -> `testpg` -> `dbmigrate` -> `app` menghalangi tes internal) yang merakit stack authz dan `organizationRoutes` di atas pool nyata, dengan middleware tes yang MENYUNTIK `authdomain.Identity`; `Scope` dan `Authorize` sungguhan dengan resolver, authorizer dan PostgreSQL nyata. Batas yang diterima: `Authenticate`, CSRF dan sesi TIDAK diuji di tes ini (tercakup di paket auth dan smoke). Kasus minimum: platform membuat organisasi; tenant yang memegang `organization.create` tetap 403 `permission_denied` (service platform-saja, butir 11); tenant tidak dapat membaca, mengubah atau mengarsipkan organisasi lain, dua arah, dengan 404 `organization_not_found` seragam; tambah dan hapus anggota mengubah hak efektif (Effective mensyaratkan keanggotaan aktif); rute tanpa hak tidak mencapai layanan dan tidak menulis audit atau event.

## Konsekuensi
- Setiap penulis baru yang mengubah status organisasi atau keanggotaan WAJIB mengambil `LockOrganization` sebagai langkah pertama transaksi dan memanggil `InvalidateInTx` di dalam transaksi (kewajiban M04 tetap berlaku untuk keanggotaan dan status user/grup).
- Pola `Access` hanya cocok untuk tabel akar tenant (`organizations`). Tabel tenant biasa (users via keanggotaan, groups, invitations) memfilter `organization_id` dari ScopeContext.
- `orghttp` bergantung pada `organization/application` (hanya `Caller` dan pemenuhan antarmuka layanan), `authorization/domain` (ScopeContext), dan `auth/domain` (Identity); lapisan HTTP tidak mengimpor repository. Pembantu paginasi offset diduplikasi dari `authzhttp` (`parsePaging`); gabungkan bersama utang `Window` saat T1b/T1c.
- Utang: `Window`/`ClampWindow` kini ada di domain organisasi (50/100) dan di domain authorization (25); gabungkan bila T1b/T1c memerlukannya.
- Repository anggota (T1a-3a) memagari `organization_id` DUA lapis: `domain.Access` tenant yang menunjuk organisasi lain ditolak di Go sebelum kueri, dan setiap SQL tetap memuat `organization_id = $1 AND ($2::uuid IS NULL OR organization_id = $2::uuid)`. Definisi "anggota aktif" (keanggotaan `active` dan `users.status = 'active'` dan `deleted_at IS NULL`) diuji silang dengan `authorization/repository.Members.IsActiveMember` supaya tidak bercabang.
- `RemoveFromGroups` menulis `group_memberships` dari paket organisasi karena paket `group` belum ada; pindahkan ke repository group saat T1c.
- `MemberService.Remove` (butir 16) memakai `RevokeUserInOrganization` (butir 15) di transaksi yang sama dengan kunci organisasi; penulis assignment lain yang mengambil kunci yang sama diserialkan dengannya, jadi assignment tidak dapat dibuat untuk anggota yang sedang dihapus di antara pencabutan dan commit.
